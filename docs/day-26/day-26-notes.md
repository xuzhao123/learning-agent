# Day 26：Hooks 与斜杠命令

## 学习目标与术语

学完能说明：harness 为什么要在固定时刻调用外部命令，四个常用事件各能做什么、不能做什么；hook 的输入输出协议怎样设计；hook 与权限规则、沙箱的先后关系；为什么 hook 配置的来源必须可信；斜杠命令和 skill 的区别。

| 术语 | 通俗解释 |
| --- | --- |
| 生命周期事件 | harness 运行到某个固定时刻（用户提交、工具执行前后、准备结束）时对外发出的通知点 |
| hook | 挂在某个事件上的外部命令：harness 把当时的情况写进它的 stdin，按它的退出码和输出决定下一步 |
| matcher | 只让 hook 在某些工具上触发的过滤条件，通常是工具名的正则 |
| 拦截 | hook 让这一步不发生：问题不发给模型、工具不执行、模型不许结束 |
| 改写 | hook 返回新的工具参数，harness 用新参数执行 |
| 失败放行 | hook 自己出错（崩溃、超时）时，harness 当作它没有意见、照常继续 |
| 斜杠命令 | 用户输入 `/名字 参数`，harness 把对应的模板展开成提示词 |

## 1. 为什么需要 hooks

模型会“经常”遵守提示词里的规矩，但不是“每次”。有些事必须每次都发生：

- 改完 Go 文件，格式必须对；
- 生成的文件不许手改；
- 代码编译不过，就不能说“完成了”；
- 用户不小心把密钥贴进对话，不能发给外部服务。

把这些写进提示词，是请求；写成 hook，是保证。hook 由 harness 在固定时刻运行，不经过模型的判断，模型也绕不过去。这和权限规则的思路一样：**确定性的约束放在 harness 里，不交给模型自觉**。

hooks 的另一个价值是扩展：团队可以用任何语言写一个小脚本接进 harness，不用改 harness 的代码。

## 2. 四个常用事件

| 事件 | 时刻 | 能做什么 | 不能做什么 |
| --- | --- | --- | --- |
| 用户提交 | 问题发给模型之前 | 拦下问题（不发给模型）；补充上下文（例如当前分支、值班表） | — |
| 工具执行前 | 权限判断之前 | 拒绝、要求确认、放行、改写参数 | 绕过用户写的拒绝规则（见第 4 节） |
| 工具成功后 | 工具已经做完 | 把反馈附在结果上给模型看（例如格式检查没过） | 撤销已经发生的副作用 |
| 准备结束 | 模型给出不带工具调用的回答时 | 不许结束，把原因交给模型接着做 | — |

“工具成功后”是事后的：文件已经写进去了，hook 只能让模型知道哪里不对、自己去改。想阻止的事要放在“执行前”。

“准备结束”是编码 agent 最有用的事件之一：编译、测试不过就把错误交回模型。它有一个风险是死循环：hook 每次都说“还不行”，模型就一直改。常见的防护有两层：harness 在输入里告诉 hook“这一轮已经因为你继续过”（Claude Code 的 `stop_hook_active`），由 hook 决定要不要再拦；harness 自己的请求预算兜底。

Claude Code 还有会话开始、压缩前后、子 agent 结束、通知等更多事件，结构相同。[资料](https://code.claude.com/docs/en/hooks)

## 3. 输入输出协议

hook 是外部命令，所以协议必须简单、和语言无关。社区的做法（Claude Code）是：

```text
harness ──stdin: JSON──▶ hook 命令 ──退出码 + stdout/stderr──▶ harness
```

输入是一个 JSON 对象：公共字段（事件名、会话 ID、工作目录），加上事件特有的字段（问题原文、工具名与参数、工具结果、是否已经因 hook 继续过）。

输出分两档：

| 退出码 | 含义 |
| --- | --- |
| 0 | 成功。stdout 如果是 JSON，按字段处理；用户提交事件的纯文本 stdout 作为补充上下文 |
| 2 | 拦截。stderr 是原因：给模型看（工具前后、准备结束），或给用户看（用户提交） |
| 其他 | hook 自己出错。记一条日志，照常继续 |

JSON 输出能表达更细的意见，例如工具执行前：

```json
{"hookSpecificOutput": {"permissionDecision": "deny", "permissionDecisionReason": "这是生成的文件，请改生成器"}}
{"hookSpecificOutput": {"updatedInput": {"command": "go test -count=1 ./..."}}}
{"decision": "block", "reason": "gofmt 没过，差异如下……"}
```

几个设计要点：

- **退出码 2 而不是 1**：很多脚本出错时随手返回 1，如果 1 就算拦截，一个写坏的 hook 会把所有操作都挡住。用一个不常见的码表示“我是故意拦的”。
- **失败放行**：hook 崩溃或超时时照常继续。这对“格式提醒”合适，对“安全检查”就不够了——安全相关的 hook 要自己保证不崩，或者把安全边界放在别处（规则、沙箱）。这是可用性与安全的取舍，没有对错，要知道自己选了哪边。
- **超时**：每个 hook 都要有时限，否则一个卡住的脚本会让整个 agent 卡住。
- **最少的环境变量**：harness 进程里往往有模型密钥，hook 用不到就不该拿到。

## 4. 和权限规则的关系

执行前 hook 排在权限规则前面：

```text
工具调用 → 执行前 hook → 规则：拒绝 › 询问 › 允许 → 权限模式默认 → 高风险确认 → 执行 → 执行后 hook
```

两条原则让 hook 不会变成后门：

1. **改写后的参数照样要过规则。** hook 把 `go test` 改成 `go test -count=1`，如果有一条拒绝规则命中改写后的命令，仍然拒绝。否则 hook 就能把一个被禁的命令“改写”进来。
2. **hook 只能收紧，不能放开用户的禁令。** hook 说“拒绝”或“询问”总是生效；hook 说“允许”只能免掉权限模式默认的那次询问，用户写的拒绝、询问规则和程序写死的高风险确认照常。理由和第 25 天“拒绝优先”相同：配置来自多个层级，任何一层都不该悄悄放开另一层的禁令。各家 harness 在这一点上的细节随版本变化，实现时以当前文档为准。[资料](https://code.claude.com/docs/en/permissions)

和第 25 天一样，hook 看到的是参数文本；可靠的边界仍然是沙箱。

## 5. 配置来源与信任

hook 是在宿主机上、以 harness 的身份运行的任意命令，不在沙箱里。所以“谁能配置 hook”是安全问题：

- 用户自己的配置：可信。
- 平台或组织下发的托管配置：可信。
- **仓库里带的配置**：不能直接信。打开一个陌生仓库，如果 harness 自动执行它带的 hook，就等于执行了仓库作者写的任意命令。

Claude Code 的做法是：项目级配置要在用户确认“信任这个目录”后才生效，组织还能用托管策略只允许托管的 hook。在没有信任确认机制之前，最简单的做法是只读用户和平台的 hook 配置。

多租户也一样：hook 运行在服务端，只能由平台配置，租户不能写。

## 6. 斜杠命令

斜杠命令是**用户触发的提示词模板**：输入 `/review 关注错误处理`，harness 读出 `review` 模板，把参数填进去，作为本轮的问题发给模型。

| | 斜杠命令 | skill |
| --- | --- | --- |
| 谁触发 | 用户明确输入 | 模型看索引后自己决定加载 |
| 适合 | 固定流程：评审、提交、按清单做任务 | 领域知识与做法：什么时候用由场景决定 |
| 失败方式 | 名字打错：直接报错，不发给模型 | 描述写得不好：模型该用时没用 |

模板常见约定（Claude Code、Codex 类似）：

- 文件放在用户目录（所有项目可用）和项目目录（随仓库共享），文件名就是命令名；
- 可选的 frontmatter 写说明和参数提示，界面输入 `/` 时列出来；
- 正文里 `$ARGUMENTS` 换成全部参数，`$1`、`$2` 换成第几个参数；正文没有引用参数时，参数追加在末尾。

命令名的识别要保守：只有 `/名字` 后面紧跟空白或结尾才算命令，`/home/user/a.txt 是什么` 这样的路径不能被当成命令；命令不存在时报错，而不是把“/拼错的名字”当普通问题发给模型。

斜杠命令只是文字，不执行任何东西，所以项目级命令的风险比项目级 hook 小得多；但它仍是会进上下文的内容，和项目指令一样要当作“仓库作者写的话”来看待。

内置命令（清空、压缩、切换模型、恢复会话）是另一类：它们是 harness 的操作，不是提示词，第 30 天做会话命令时再加。Claude Code 后来把自定义命令并进了 skills：一个 skill 既能被模型自动加载，也能用 `/名字` 手动触发。[资料](https://code.claude.com/docs/en/slash-commands)

## 自测

**为什么“改完必须 gofmt”适合写成 hook，而不只是写进项目指令？**

项目指令是请求，模型大多数时候会遵守但不保证；hook 每次都由 harness 执行，模型绕不过去。

**执行后 hook 发现写进去的文件有问题，能把写入撤销吗？**

不能。副作用已经发生，它只能把反馈附在结果上，让模型自己改。要阻止的事放在执行前。

**为什么拦截用退出码 2，而且 hook 自己出错时照常继续？**

1 是脚本出错时最常见的退出码，用 2 区分“故意拦截”和“意外出错”。失败放行保证一个写坏的 hook 不会让 agent 完全不能用；代价是安全类 hook 崩了就等于没有，所以安全边界不能只靠 hook。

**执行前 hook 把命令改写成被拒绝规则命中的形式，会怎样？**

仍然被拒绝。改写发生在权限判断之前，改写后的参数要重新过规则；hook 只能收紧，不能放开用户的禁令。

**打开一个陌生仓库时，为什么不该自动执行它带的 hook？**

hook 在宿主机上以 harness 的身份运行任意命令，不在沙箱里。自动执行仓库带的 hook，等于执行仓库作者的代码；要先有用户确认的信任机制。

**斜杠命令和 skill 的根本区别是什么？**

谁来触发：命令由用户明确输入，skill 由模型根据索引自己决定。
