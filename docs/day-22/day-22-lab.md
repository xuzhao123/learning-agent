## 2. 拆细后看出的两个问题

**并行调度没区分只读和修改。** `agent.ExecuteBatch` 把同一批工具调用都放进并发槽位，见 [react.go](../../internal/agent/react.go)。目前的工具大多是只读的或彼此独立，问题不明显；D23 加入编辑和写入后，两次修改同一个文件的调用并行执行会互相覆盖。Claude Agent SDK 的做法是只读工具并行、修改类工具串行，并用工具标注里的 `readOnlyHint` 区分。

**凭证隔离只做了一半。** Bash 沙箱用 `--clearenv` 清空环境，只设 PATH、HOME 等固定变量、代理地址和调用链变量，并把挂进来的项目 `.env` 盖成空文件，见 [sandbox.go](../../internal/sandbox/sandbox.go)；但第三方 MCP stdio server 用 `client.NewStdioMCPClientWithOptions` 启动，传入的环境为 nil，会继承 agent 的全部环境变量，包括模型密钥，见 [mcp.go](../../internal/mcp/mcp.go)。

这两个问题都放进了下面的任务集。

## 3. 自用任务集

选题标准见笔记第 9 节：来自 `PROJECT.md` 的真实待办，改动小，用编译和一次真实运行就能判定，覆盖不同的 harness 能力。

| 编号 | 任务 | 来源 | 大致改动 | 主要考验 |
| --- | --- | --- | --- | --- |
| T1 | 计算器工具描述写明不支持乘方 | D17 归因：子 agent 因此每次多一轮 | `internal/tools/tools.go` 一行描述 | 读、精确替换 |
| T2 | `go run . metrics` 汇总首字延迟 | B1 遗留 | 从 `.data/traces` 里模型调用 span 的 `agent.response.first_token_ms` 取值，按 P50/P95 输出 | 跨文件阅读、理解数据来源 |
| T3 | 第三方 MCP stdio server 只拿最小环境 | 待办“MCP 权限” | `internal/mcp` 启动时传显式环境白名单 | 读懂第三方库行为、安全相关修改 |
| T4 | 只读工具并行、修改类工具串行 | 本日对照发现 | `agent.ExecuteBatch` 按工具标注分组调度 | 并发逻辑、改动影响面大 |
| T5 | 检查点加格式版本号 | 待办“检查点” | `Checkpoint` 加版本字段，读取时检查 | 数据兼容、读旧数据 |
| T6 | 观测台沙箱文件面板支持删除 | D12 遗留 | `internal/observer` 加删除接口与按钮，只经 `os.Root`、核对租户、写审计 | 前后端一起改、守住已有安全约束 |

完成判据：每题都要 `gofmt -l` 无输出、`go build ./...` 通过，另加一次真实运行检查：

| 编号 | 真实运行检查 |
| --- | --- |
| T1 | 用真实模型问一道含乘方的计算题，模型不再先调用计算器再失败 |
| T2 | 跑一个真实任务后，`go run . metrics` 输出首字延迟，数值与该次协议事件和 span 里的 `first_token_ms` 一致 |
| T3 | 启动一个打印环境变量的 stdio server，看不到 `ARK_API_KEY`、`DEEPSEEK_API_KEY` |
| T4 | 一次回复里同时有两个读和一个写时，事件顺序显示两个读重叠、写单独执行 |
| T5 | 新版本能读旧检查点并续跑；版本号不认识时给出明确错误 |
| T6 | 本租户能删自己的文件；越权、路径穿越、链接都被拒绝，并且审计里有删除记录 |

使用计划：

| 时间 | 用法 |
| --- | --- |
| D28 | 编码工具、权限与 hooks 补完后，挑 T1 或 T5 让 harness 第一次真正改代码，记录卡在哪一步 |
| D36 | 给每题配校验命令，整理成编码任务评测集 |
| D41 | 用 harness 完成 T3、T4 或 T6 中的一题 |

在 harness 能改代码之前，这 6 题都不手工修；否则后面就没有真实任务可用。
