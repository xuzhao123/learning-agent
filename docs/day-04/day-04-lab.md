# Day 4 项目实践：在 Agent 中实现工具式 RAG

原理见 [Day 4 学习笔记](day-04-notes.md)。本文只记录本项目怎样实现、怎样动手观察，以及实验结果。公共启动与模型配置见根目录 [README](../../README.md#模型与工具配置)，本课动手步骤见下文。

## 1. 实现概览

```text
窗口外：24条FAQ → embedding向量 → Go内存索引（磁盘缓存）
                                   ↑ search_docs(query, k)
窗口内：system → user → assistant(tool_calls) → tool(片段) → assistant(回答 [D05])
```

| 设计点 | 本项目的选择 |
| --- | --- |
| 检索位置 | 工具式：`-rag` 注册 `search_docs`，复用原 ReAct 循环、重试、步数预算与上下文管理 |
| 语料与切块 | [corpus.md](../../retrieval/corpus.md) 24 条 FAQ，按二级标题切块；`标题 + 正文` 向量化，来源作元数据 |
| 向量模型 | `-embedding local`：paraphrase-multilingual-MiniLM-L12-v2，Hugot 纯 Go 推理，384 维；`-embedding ark`（默认）：doubao-embedding-vision-251215，1024 维，只请求稠密向量 |
| 非对称检索 | 线上模式入库与查询分别使用不同指令 |
| 相似度 | 向量归一化后逐条点积，即余弦相似度；24 条无需向量数据库 |
| 召回参数 | k 默认 3，范围 1–6；阈值 `-min-score` 默认 0.40，低于阈值的候选清空正文，只留编号、标题、分数、来源 |
| 索引版本 | 指纹包含模型、维度、指令与语料；缓存在 `.cache/retrieval-go/`，任一项变化即重建 |
| 进程与资源 | 检索与 Agent 同进程；普通任务不加载向量模型。本地模式单进程峰值内存约 1.6GB，每次启动都要加载模型；线上模式每次查询请求一次 API |

已知边界：只实现向量召回；BM25、重排、上下文化切块未实现。FAQ 是人工整理的项目事实，代码变化后需同步。

检索结果仍由这一行写回历史，RAG 没有新增循环：

```go
conversation.Append(Message{Role: "tool", ToolCallID: observation.ID, Content: string(data)})
```

## 3. 动手

1. 网页 `go run . observe`：新对话勾选"知识库 RAG"，选择向量模型，问"工具失败总共尝试几次，等待多久？"
2. 展开 search_docs，比较 query、候选编号、分数与正文；低于阈值的候选没有正文。
3. 切到"观测"，在下一次请求的 messages 里找到 `role=tool` 的片段。
4. 点击回答中的引用核对原文。蓝色引用是本题实际取回且过阈值的片段；红色删除线表示没有取回或低于阈值，不能作为证据。
5. 新对话分别问酒店报销和 TS-999，区分"主题缺失"和"主题相关但事实缺失"。
6. CLI 比较两种向量模型的分数分布：`go run . -search-docs '这个项目压缩时承诺保留最后两组消息吗？' -embedding local`，再换 `ark`。本地模式第一名是 D12，D11 排第二；线上模式只有 D11 过阈值。

## 4. 10 题对照实验

题目与人工评阅依据在 [questions.json](../../retrieval/questions.json)，`answer_hint` 不发给模型。8 题库内可答，2 题库外。题库在调试中使用过，不是留出集。

**直接检索（k=3，阈值 0.40，相关文档排名第一时的分数）**

| 问题 | 相关文档 | 本地 MiniLM | 线上 Doubao |
| --- | --- | --- | --- |
| Q01 请求预算 | D04 | 0.7192 | 0.5473 |
| Q02 重试与等待 | D05 | 0.5993 | 0.5621 |
| Q03 并行数量 | D02 | 0.7661 | 0.5109 |
| Q04 重复判定 | D06 | 0.7595 | 0.5469 |
| Q05 输入容量 | D08 | 0.7837 | 0.7052 |
| Q06 最近组保留 | D11 | 0.5964（第 2 名） | 0.5054 |
| Q07 观测台续聊 | D14 | 0.6034 | 0.5295 |
| Q08 49% 实验条件 | D22 | 0.8008 | 0.6703 |
| Q09 酒店报销（库外） | 无 | 最高 0.2130，全部过滤 | 最高 0.2162，全部过滤 |
| Q10 TS-999（库外） | 无 | 最高 0.4811，过阈值但无定义 | 最高 0.2745，全部过滤 |

两种模式可答题 hit@3 均为 8/8。线上分数为 2026-10-04 改为只请求稠密向量后重建索引的结果，与改动前相差不超过 0.01，命中情况不变。本地 Q10 过阈值却没有答案，说明阈值不能代替正文核对；两列分数分布不同，不能横向比较。

**问答对照**（记录 `20261004-195200.394`，线上向量，`doubao-seed-2-1-pro-260628`，minimal 推理，每题每组最多 6 次请求；此次运行早于稠密向量改动）

| 指标 | 无检索 | 有检索 |
| --- | --- | --- |
| 库内题答对 | 0/8，均说明资料不足 | 8/8 |
| 可答题有效引用 | 0/8 | 8/8 |
| 库外题合理拒答 | 2/2 | 2/2 |
| 人工发现的无依据断言 | 0/10 | 0/10 |
| 检索调用 | 0 | 12 次，覆盖 10/10 题 |
| 聊天模型请求 | 10 | 22 |
| 聊天 API 总 token | 1,997 | 25,386 |

结论：本轮无检索组选择了拒答，未观察到编造；检索提高了能基于资料回答的比例和可核查性，代价是更多请求与 token（不含 embedding 成本）。Q06 模型主动追加了两次检索。引用逐项核对过，全部指向本题实际返回、过阈值且支持结论的正文。

实验设计说明：两组使用相同的回答标准、模型、推理强度与预算；系统提示如实说明本轮有无检索工具；无检索组移除全部文档工具，避免 search_notes 泄漏资料；每题独立上下文。单题超出预算或网络失败时记录 `RAG case failed` 并继续，最后汇总失败数，失败题按未答对计。

调试中出现过：跳过检索直接拒答、引用正确片段却说反否定关系、引用未过阈值的候选。对应修正为：明确项目范围与工具可用性、改写易误读的 FAQ 表述、在检索函数中清空低分正文。召回、生成、引用需要分层检查。
