# Day 36：编码任务评测集

## 学习目标与术语

学完能说明：编码 agent 的评测题由哪几部分组成；“做完了没有”为什么要由校验命令而不是模型自己的回答来判定，校验命令本身又要怎样隔离；“自称完成”和“真的完成”分开记，能看出什么；一道题怎样证明它出得对（可解、能区分）；跑评测时最容易踩的污染是什么。

| 术语 | 通俗解释 |
| --- | --- |
| 仓库快照 | 一道题的起点：某个仓库在某个时刻的样子（一个提交，或一个小的示例仓库） |
| 任务说明 | 交给 agent 的那段话：要改什么、约束是什么 |
| 校验命令 | 改完以后跑的一条命令，退出码为 0 就算达到；它属于题目，不属于被测的 agent |
| 自称完成 | agent 自己正常结束，给出了“做完了”的回答 |
| 误报 | 自称完成，校验却没过 |
| 参考解 | 出题人自己做的一份正确改动，用来证明这道题可解、校验命令能判对 |
| 污染 | 几个试次共用了同一份环境，前一个的结果影响了后一个 |

## 1. 一道编码题由什么组成

问答题的“答案”是一段文字，编码题的“答案”是对一个仓库的改动。所以题目要固定的是：

```text
起点（仓库快照） + 任务说明 + 校验命令
```

Terminal-Bench、SWE-bench 这类基准都是这个结构：SWE-bench 的起点是真实开源仓库在某个 issue 提出时的提交，校验是那次修复附带的测试；Terminal-Bench 的起点是一个容器环境，校验是一组脚本。自己的评测集也一样，题目最好来自**真实失败过的任务**：它们代表了自己的 harness 在自己的工作里真的会遇到的问题。

## 2. 为什么要校验命令，又为什么要隔离

只看模型的最终回答，“我已经改好并测试过了”和真的改好了无法区分。校验命令把“做完没有”变成可以重复执行、看退出码的事。

但校验命令跑的是**被测的模型刚改过的代码**。如果直接在评测机器上跑：

- 模型写进仓库里的东西会在评测机器上以评测程序的权限执行；
- 校验命令可能顺手改动现场，下一项检查看到的就不是模型留下的样子；
- 需要的环境（编译器、浏览器）和 agent 工作时的不一样，结果不能代表 agent 自己能验证到什么。

所以校验命令应该在和 agent 干活时同样的隔离环境里跑，工作区只读挂载；校验需要的脚本放在模型改不到的地方。

## 3. 好的校验命令

| 要求 | 例子 |
| --- | --- |
| 检查行为，不只检查文本 | “构建出来的程序 `pow 2 10` 输出 1024”，比“源码里出现 pow”可靠 |
| 覆盖说明里的每条约束 | 说明写了“参数错误时非 0 退出”，就要有一条错误参数的检查 |
| 不依赖网络与时间 | 任何时候重跑结果都一样 |
| 页面题要真的操作页面 | 悬浮效果要用真实浏览器把鼠标移上去，再看“看得见的文字”；只检查有没有某个属性，过不了真实的人 |
| 能分清“没做”和“做错” | 失败时打印是哪一条没过，便于归因 |

**证明题目出得对**：每道题在起点上跑一次校验（必须失败，否则题目无效），再在参考解上跑一次（必须通过，否则校验命令写错了）。这和问答题的“参考答案”是同一个作用。

## 4. 自称完成与真的完成

每个试次记两件事：agent 是否正常结束（它自己认为做完了），校验是否通过。四种组合：

| | 校验通过 | 校验没过 |
| --- | --- | --- |
| 自称完成 | 真的完成 | **误报**：最需要关注 |
| 没正常结束（预算用完等） | 做到了但没收尾 | 没做完 |

误报率高，说明 agent 的“自检”不可信：需要更强的完成判定（独立验证、收尾检查），而不只是让模型更努力。

## 5. 污染

编码题的环境是可写的：前一个试次改过的文件，如果下一个试次还能看到，后一个就不是在原题上做了。每个试次都要从起点拿一份**新的拷贝**，跑完存下改动（diff）供归因，再把拷贝删掉。回放、消融同样适用：对照组和实验组都要从同一个干净的起点开始。

## 自测

1. 编码题的“答案”是什么？题目要固定哪三样？
2. 校验命令为什么不能直接在评测机器上跑？
3. 怎样证明一道题出得对？
4. “自称完成但校验没过”说明什么？应该从哪里改？
5. 为什么每个试次都要一份新的仓库拷贝？

### 自测答案

1. 答案是对仓库的改动；固定起点（仓库快照）、任务说明、校验命令。
2. 它执行的是模型改过的代码，有安全风险；可能改动现场影响后续检查；环境和 agent 工作时不同。应在同样的隔离环境里只读运行。
3. 在起点上跑校验必须失败，在参考解上跑必须通过。
4. agent 的自我判断不可信：要加独立的完成判定（校验命令、另一个判定者、收尾检查），而不是只靠提示词让它“认真检查”。
5. 编码题会改环境；共用一份时前一个试次的改动会影响后一个，结果就不是在原题上做的。
