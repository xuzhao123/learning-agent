# 观测台使用与实现

观测台与 agent 共用同一个程序。它启动任务子进程、代理模型请求、记录过程，再把同一份数据展示为对话和观测视图。源码见 [internal/observer](../../internal/observer/)，公共配置见 [README](../../README.md)。

## 1. 启动

在项目根目录执行。观测台需要登录，先添加账号（密码从标准输入读，终端里不回显）：

```sh
go run . observe -add-user admin                  # 平台账号
go run . observe -add-user alice -tenant acme     # 租户账号
go run . observe
# 打开 http://127.0.0.1:8090 登录
```

| 参数 | 默认值 | 用途 |
| --- | --- | --- |
| `-addr` | 127.0.0.1:8090 | 页面监听地址 |
| `-dev` | false | 每次任务用 go run . 启动，读取最新 agent 源码 |
| `-add-user` | 空 | 添加或重设账号后退出；配合 `-tenant`（不给为平台账号）、`-features`（租户可用功能，逗号分隔）、`-max-running`（租户同时运行的对话上限，默认 2） |

**平台账号**看到 `.data/` 下原有的对话、记忆与审计，可以使用评测、归因、修改 Skills/MCP 配置和全局指标。**租户账号**只看到自己租户（`.data/tenants/<租户>/`）的对话、记忆和审计，评测与归因入口不显示，设置页里未开通的工具显示为“不可用”，工作区要租户明确开通 `workspace` 才能用；别的租户的对话按编号访问一律返回“找不到”。登录、会话与隔离的实现和验证见 [Day 20 实践](../day-20/day-20-lab.md#6-多租户与登录补充)。

默认直接执行当前程序的 agent 模式，因此改了 agent 代码要重启观测台；`-dev` 每次任务多一次编译。观测台代码或内嵌页面改动后，两种模式都需要重启并刷新网页。配置、skills、学习笔记和运行目录相对于项目根目录。

## 2. 新对话、续聊与定位

1. 点击“新对话”，在输入框下方选模型和工作区，输入问题。模型分两级：先选供应商（豆包 / DeepSeek），供应商的清单里有多个模型时旁边再多一个下拉选具体模型（如 `kimi-k3`）；清单只有一条时这一级自动隐藏。工具不在这里勾选，由设置决定（见下一节）。Enter 发送，Shift+Enter 换行；输入法选词的 Enter 不发送。
2. 回答结束后继续输入，沿用当前对话；先选择左侧旧记录，也可以继续那条对话。
3. 运行中和回放中不能续聊。停止、超时或出错后的恢复方式见第 6 节。
4. 点击“新对话”开始独立任务，不删除旧记录。
5. 附图：输入框左下角的图片按钮、粘贴截图或把图片拖到输入区。只收 PNG、JPEG、GIF、WebP，单张不超过 20 MB，每条消息最多 8 张；图先上传存好，输入框上方显示缩略图，点 × 去掉。所选模型（续聊时是这条对话的模型）不能看图时按钮变灰，悬停说明原因；已经附了图又换到不能看图的模型，发送时拦下并保留图。对话里用户气泡下显示这一轮的图，点开看原图；模型用 `view_image` 看过的图显示在那次工具调用的结果里。

顶栏显示对话 ID 的前 8 位，点击复制完整 ID。地址 `/?run=<对话ID>` 支持链接直达、刷新恢复和浏览器前进/后退。存档名是 `.data/runs/<对话ID>.jsonl`；续聊保留同一对话 ID，但每次执行启动新的 agent 进程。

一段对话固定供应商、具体模型和工作区；具体模型记在 start 事件的 `model` 上（空表示用这家供应商的默认值），以 `-model` 启动参数交给 agent，所以中断续跑与归因回放也用同一个；agent 实际用的是哪一个由它的 `turn/started` 通知补上，打开已有对话时第二级下拉只显示这个名字。开始时的设置快照（工具、向量模型、记忆有效期、请求预算、上下文窗口、工具输出上限）也写进 start 事件，续聊照它启动 agent。之后改设置、改能力中心的开关，只影响新对话。

界面风格参照 Codex 客户端：黑白灰为主，颜色只用于状态（失败、运行中）；图标是内联 SVG，不依赖系统字体；成功的工具调用不加标记，只标出失败和非零退出码；输入框下只在需要人注意时出现提示。

### 2.0 导入其他 agent 的对话

左侧“导入对话”上传 Codex 的 `rollout-*.jsonl` 或 Claude Code 的会话 `.jsonl`，转成同一种存档后只读查看，列表里标题前标出来源。格式、切分规则与缺失项见 [导入实践](../bonus-import/import-lab.md)。

### 2.1 设置

左侧“设置”参考 Claude Code 的 settings.json、Codex 的 config.toml：工具常驻，模型自己决定用不用，每个对话只选模型和工作区。

| 内容 | 规则 |
| --- | --- |
| 合并顺序 | 内置默认 › 平台 › 个人；每项旁边标出来自哪一层。保存时只存和上一层不同的项，平台默认改了，没单独设过的人跟着变 |
| 只会关、不会开 | 租户没开通的功能、本机跑不了的工具（没有 bubblewrap、没找到 Chrome、线上向量缺 ARK_API_KEY）显示“不可用”和原因，新对话不带上 |
| 单个工具 | 内置的计算器、当前时间、笔记检索，和浏览器的必应搜索（web_search）、打开网页（open_page）各有开关；关掉的写进快照的 `disallowed_tools`，agent 用 `-disallowed-tools` 去掉（与 Claude Code 同名；它只是把工具从清单里拿掉，按调用拦截是权限规则的事），系统提示词只写带上的浏览器工具。命令行和评测不经过设置，照常带内置工具 |
| 默认关的项 | 知识库检索（它的系统提示词要求知识问题先查资料）、长期记忆（每个新对话先多发几次模型请求做召回）、笔记检索（只查第 1 天的一篇笔记，通用问题模型也会先去查）、必应搜索（必应多半不给自动化浏览器结果；搜索交给 DeepSeek，浏览器只留打开网页） |
| 工作区 | 平台账号登记本机已存在的 git 仓库；对话只能从列表里选，网页只传名字，目录由服务端解析。租户必须明确开通 `workspace` |
| 默认值 | 默认模型、默认工作区、请求预算（默认 0，即不限：靠重复动作与无进展熔断、停止按钮收住；快照里记 -1）、上下文窗口（默认 262144：编码任务跨多个文件，D27 实测 64K 下反复压缩做不完）、工具输出上限（默认 4000） |

设置存 `.data/settings.json`（不提交），实现见 [settings.go](../../internal/observer/settings.go)。

D25 起设置里还有默认权限模式和权限规则（一行一条，如 `allow: Bash(go build *)`、`deny: Bash(git push *)`）。输入框旁的“权限”每轮都能换：新对话取设置的默认，续聊取上一轮的；规则在对话开始时拍进快照。“改动都问”模式下，改文件、跑 bash 前出现和 D20 一样的确认卡片，风险标为“权限设置要求确认”。见 [Day 25 实践](../day-25/day-25-lab.md)。实验（上下文、检索、内容与权限）仍在左侧“实验”分组里单独运行，不受设置影响。事件时间存 UTC，页面按浏览者的时区显示；ID 使用随机 UUID，不作为时间排序依据。

D26 起设置里有 Hooks（只有平台账号能改，个人层改它返回 403）：填配置原文或相对 agent 目录的路径，如 `hooks/hooks.json`，对话开始时读成原文拍进快照。对话里，工具前后的 hook 显示为工具上方的 HOOK 卡片，Stop hook 显示在被拦下的回答下面，用户提交的 hook 归到本轮开头的能力卡片。输入框打 `/` 列出斜杠命令（个人级 `commands/`，加上所选工作区的 `.agents/commands/`）。

## 3. Turn、Step 与原始输入输出

| 概念 | 含义 |
| --- | --- |
| Turn | 一次用户提问及其执行过程；续聊开启下一个 Turn |
| Step | Turn 内的一次任务模型调用，以及该调用发起的工具执行 |
| 请求 #N | 同一记录中的全局模型调用序号，续聊后继续累计 |
| 压缩/辅助调用 | 单独记录的摘要、记忆背景或重排请求；不是新的用户提问 |

Step 从 1 重新编号。上下文摘要不占任务 Step，但计入模型请求预算；辅助调用的用量也参与总量统计。

每个 Step 的“原始输入 / 输出”开关展开两张 JSON 卡片，包含行号、着色、滚动和复制。请求进行中输出卡片显示等待状态，响应后更新。展开状态与 Turn 的折叠状态独立，切换对话/观测标签后保留。

运行中的对话默认跟随最新输出。往上滚（滚轮、拖滚动条、键盘、触摸）就停止跟随，位置不再被拉回；底部出现“回到最新”，有新输出时带圆点，点它或滚回底部恢复跟随。流式增量只就地更新最后一次请求的思考和正文，页面其余部分不重建，所以点击、选中文字不受影响。思考框在输出中也可以展开，展开后从最新内容看起并继续跟随。

- **输入**：本次完整请求体；messages 包含 system、此前 user/assistant/tool 与本轮新输入，全部按实际顺序展示。
- **输出**：本次完整响应体；包含 choices、tool_calls、推理字段、usage 等，或原样记录的错误文本。
- **工具定义**：位于 tools 字段，单独展示，不计入 messages 数量。
- **历史**：是本次输入的一部分；它不是新发生的事件，不会每轮在主表重复展开。

例如同一问题先检索再计算，输入可能依次是：

```text
Step 1：system + user                                      = 2 条
Step 2：上面两条 + assistant(tool_calls) + tool(检索结果)     = 4 条
Step 3：上面四条 + assistant(tool_calls) + tool(计算结果)     = 6 条
```

这些请求属于同一个 Turn。主表展示新的调用和结果，Step 详情展示本次实际发送的全部消息。压缩后的保留原话与交接摘要仍按 API 角色展示，不再误标为新的用户提问。JSON 复制不包含行号，原文用文本节点展示。

## 4. 对话与观测视图

### 4.1 对话流

对话流从协议数据还原：

```text
用户消息     ← start/continue 或实验中的新问题
思考/回答    ← assistant 响应
工具卡片     ← tool_calls + 后续 tool_call_id 对应的结果
压缩分隔线   ← 上下文摘要调用
停止状态     ← 进程退出事件与终端输出
```

工具调用请求不等于工具已经执行；结果通常在下一次模型请求的 role=tool 消息中出现。保留的旧用户消息不重复显示为新问题。回答下方的“观测”定位到相应响应，来源引用定位到工具结果。

回答只渲染少量 Markdown：标题、列表、表格、代码块、行内代码、粗体和链接。先转义再替换，模型输出不能注入 HTML。链接只认 http(s)，`[文字](地址)`、`<地址>` 和裸地址都会变成新标签页打开的链接；地址只取 ASCII 字符，紧跟的中文标点不算进去，行内代码里的地址不变。用户消息按原文显示，不做渲染。

### 4.2 轨迹

轨迹按 **Turn → Step → 事件** 分组：

| 事件 | 展示内容 |
| --- | --- |
| SYSTEM | 初始化或发生变化的系统规则与工具定义 |
| USER | 新提问 |
| ASSISTANT | 思考、工具请求或回答 |
| TOOL | 参数、执行结果与状态 |
| COMPACTED | 摘要与上下文重建 |
| EXIT | 任务进程结束状态 |

同批并行工具位于同一个 Step，依赖前一步结果的调用进入下一 Step。最终回答已经是 ASSISTANT 事件，不再重复增加回答行。

右侧瀑布时间轴展示实际耗时；拖拽刻度聚焦，双击还原。点击 Step 的“X 条 messages”查看完整输入，点击事件查看输出、参数、结果、Schema 和原始 JSON。当前模型请求非流式，只能显示总耗时，不能拆分 TTFT 与 decode。

分组参考 [DeepSeek Harness 官方 Trajectory 源码](https://github.com/deepseek-ai/deepseek-harness/blob/5badb15009ae1756c3afe0ae0cef1faafc290ccc/packages/client/ui-trajectory/src/client/layout.ts)。其中 CONTEXT 指程序注入消息，不是全部历史的统称；本项目从请求与首问/续聊事件还原过程。

### 4.3 迷宫

模型请求组成主干，工具分支执行后汇合。错误、空结果或相同参数的重复调用标为绕路；绕路后再调用同名工具，画出回退弧。判定由固定规则完成，可在详情里查看依据，不能当作答案质量评分。

下方三条数据轨分别展示工具调用密度、token 构成和上下文压力。输入容量优先读取 agent 的 Context 输出；压缩标记来自摘要或视图重建，不把任意 token 下降当成压缩。

API 输入 token 曲线与 agent 触发压缩时的 used 口径不同：后者还包含上次完成量和增量估算。共同消息前缀也不等于服务端一定命中缓存。策略见 [Day 3 实践](../day-03/day-03-lab.md)。

### 4.4 对比与回放

勾选 2–5 条记录，对比模型/工具调用数、绕路、tokens、缓存、耗时和答案，并按全局请求序号对齐。点击泳道中的模型或工具格子查看原始事件。

已结束的运行支持 1×–300× 回放；“折叠空闲”缩短没有活动的等待段。相同问题的模型决策可能不同，耗时或调用更少不自动代表回答更好。

### 4.5 调用链

“调用链”标签读取 OpenTelemetry span（D13）。每次首问或续聊是一个 trace，根 span 是观测台的 `interaction`；agent、子 agent、MCP server 等进程的 span 通过 `TRACEPARENT` 或 `_meta.traceparent` 挂在它下面。

- 上方指标由 span 汇总：模型与向量化的次数、失败率、P50/P95 与 token，各工具的耗时与失败率，任务结局；默认只统计本对话，可切换为全部对话。
- 每个 Turn 一棵 span 树和瀑布条，耗时是 span 的真实起止时间，不是两次模型请求之间的间隔。
- 点击 span 查看属性与事件（重试、不重试原因、拿到并发槽位等）；chat span 可以跳到“轨迹”里对应的原始请求，两者靠请求头里的 `traceparent` 对上。
- 标黄的 span 找不到父节点：父 span 还在运行，或进程被强制结束。
- D13 之前的对话没有 trace。

实现与实验见 [Day 13 实践](../day-13/day-13-lab.md)。

## 5. 工具能力与审批

### 5.1 检索和记忆

在设置里打开“知识库检索”，选择线上方舟或本地 MiniLM（和长期记忆共用）。检索直接在 agent 进程内调用，续聊沿用快照。

search_docs 的候选卡片展示编号、标题、score、阈值、接受状态、正文和来源。低分片段不返回正文，但仍可能有元信息；“通过阈值”不是事实验证。答案中的 [Dxx] 只有此前实际检索到且通过阈值时才形成有效引用；截断后不能解析的结果显示原文。

长期记忆的调入、检索、写入和删除可在卡片或记忆面板观察。记忆背景与重排请求作为辅助调用分开标注，不混成用户消息。实践见 [Day 4](../day-04/day-04-lab.md)、[Day 5](../day-05/day-05-lab.md)。

### 5.2 Skills 与 MCP 中心

中心管理能力的配置，扫描、校验、连接和工具发现仍由 agent 执行：

| 操作 | 执行方式 |
| --- | --- |
| 列出 skill | agent 的 -skills-list |
| 新建 skill | 写 skills/&lt;name&gt;/SKILL.md 后校验；不合规撤销 |
| 测试 MCP | agent 的 -mcp-server … -mcp-list，不请求聊天模型 |
| 创建对话 | 把已启用能力写入 start 快照 |
| 续聊 | 从存档快照恢复能力，避免历史工具集合发生变化 |

MCP 配置可填 stdio 启动命令或 http(s) 地址。源码启动命令相对项目根目录执行；首次 go run 需要编译，后续可复用 Go 缓存。

观测台内置远程地址为 `http://127.0.0.1:8090/mcp`，在中心“快速填入 → observer”添加。它由观测台进程处理，复用 [mcp.go](../../internal/mcp/mcp.go) 的 calculator server 定义；无需另外启动服务。同一定义也可通过 -mcp-serve 提供 stdio，或加 -mcp-http 提供独立 HTTP 服务。

中心能启动本地命令，因此接口检查本机 Host 和同源 Origin。第三方 server 的权限边界见 [Day 7](../day-07/day-07-lab.md)。

### 5.3 子 agent 与浏览器

设置里打开“子 agent”后，spawn_agent 卡片可打开右侧侧栏，查看子任务原文、过程和结果。请求通过 X-Agent-Task 区分父子任务，子请求不混入父对话流。实践见 [子 agent](../bonus-subagents/subagents-lab.md)。

设置里的“必应搜索”“打开网页”分别对应 web_search、open_page（默认只开打开网页），每次调用一个标签页。侧栏显示最新调用画面，结束后保留最后一帧；后续调用切到新的画面。画面读取自 `.data/browser/<任务ID>/<调用ID>.jpg`。浏览器需要本机 Chrome/Chromium；实践见 [Day 11](../day-11/day-11-lab.md)。设置里的“DeepSeek 搜索”增加 ds_search/ds_fetch，在 DeepSeek 服务端执行，没有画面；没有 `DEEPSEEK_API_KEY` 时设置页显示不可用。

### 5.4 Bash 与网络审批

设置里打开“Bash 沙箱”启用 bash 和 request_network_access。bash 的 `/workspace` 是对话自己的沙箱目录，还看不到对话选的工作区（计划在 D24–25 挂载）。同一对话的各轮共用一个工作目录（`/workspace`），子 agent 各有自己的；同批 Bash 顺序执行；命令非零退出仍返回结果，不自动重试。

第一轮开始后，顶栏出现“沙箱文件”：右侧列出这个对话 `/workspace` 里的文件，点开预览文本或图片，其他类型下载查看；每轮结束自动刷新。“上传文件”把文件放到 `/workspace` 顶层，不覆盖同名文件，单个不超过 10 MB，运行中不能上传；上传后在下一条消息里告诉 agent 文件名。这些文件是模型写的不可信数据：符号链接不跟随，下载一律按附件返回。实现与验证见 [Day 12 实践 3.7](../day-12/day-12-lab.md#37-对话级沙箱与文件进出)。

模型只能请求联网，用户点击“允许”后才加入白名单。B0 起这是 agent 发给观测台的请求（`network/requestApproval`）：agent 暂停等待，用户在对话流的卡片上点“允许”，观测台当场回复，**本轮**接下来的命令就能访问；最多等 4 分钟，没有答复时 agent 返回待批准并结束本轮。子 agent 发起的审批经父 agent 转发到同一张卡片。决定同时记入存档，之后的续聊作为 `-net-allow` 传入。浏览器是独立网络通道，不受 Bash 白名单直接约束。隔离、资源条件和组合风险见 [Day 12 实践](../day-12/day-12-lab.md) 与 [Q12](../deep-questions.md#q12)。

D20 起还有高风险操作确认（`tool/requestApproval`）：删除记忆、MCP 声明的破坏性工具、任务读到私有数据后的浏览器与 MCP 调用、续跑时重做中断的操作，执行前在对应工具上方出现“需要你确认”卡片，显示风险、原因和完整参数。“允许”只对这一次调用有效；外发类另有“本对话内 … 都允许”（范围是工具名，读网页再加主机），之后同一范围不再询问，续聊沿用。agent 结束时仍未答复的显示为未答复。决定记为 decision 事件（`allow`、`allow_session` 或 `deny`）。见 [Day 20 实践](../day-20/day-20-lab.md#2-在观测台里操作)。

D21 起，点“允许 / 拒绝”（工具确认与联网审批）时观测台先写审计日志，再回复 agent；写不进就不回复。左侧“审计日志”只读展示 `.data/audit/audit.jsonl`，每次打开从头校验哈希链，可按任务过滤、跳回对话。见 [Day 21 实践](../day-21/day-21-lab.md#3-查看与校验)。

## 6. 停止与恢复

运行中发送键变为 ■：

- 第一次点击经协议发 `turn/interrupt`（拿不到确认时退回 SIGINT），优雅停止、回填调用状态并保存检查点；父 agent 向子任务传递停止信号。
- 正在停止时再点一次，确认后强制结束，未保存的进度可能丢失。
- 取消中的模型请求记录为 499，与上游故障区分。

正常结束后，续聊从最后一次普通请求和完整 assistant 回答恢复 View。停止、超时或出错后，从任务检查点恢复。每一轮都用新的检查点 ID，并以 `continues` 指向上一轮，旧检查点保持原样；模型可以用 task_id 引用之前各轮派出的子任务，让它们从检查点续跑；缺少结果的工具调用补为“未执行”或“结果未知”，不会在恢复历史时直接重做。之后模型根据新消息决定核对、重做还是放弃。

恢复的是模型视图，不重新注入全部压缩前原文；更早轨迹仍在观测存档中。每次新提问获得新的请求预算，Turn 连续递增，Step 从 1 开始。整条记录的时间跨度包含两次提问之间的等待。底层语义见 [Day 8](../day-08/day-08-lab.md)、[Day 9](../day-09/day-09-lab.md)。

选了工作区的对话，对话结束后每条用户消息下面有“撤销到这一轮之前”：先预览会恢复、删除哪些文件，有冲突（agent 最后一次写入之后文件又被改过）只提示、不执行；确认后这一轮及之后各轮用编码工具改过的文件放回去，这几轮淡化显示，下一条消息从被撤销那一轮的上一轮接着聊（取它的检查点）。连第一轮也撤销后不能再续聊。bash 改的文件没有快照。实现与验证见 [Day 29 实践](../day-29/day-29-lab.md)。

续聊的每一轮，用户消息下面显示“闲置多久 · 首次请求缓存命中多少（多少 token 未命中）”：隔得越久，提示词缓存越可能已过期，整段上下文要按全价重新处理。过长的工具结果在对话里只显示预览（`saved_output`），完整内容在 `.data/outputs/` 下，模型用 `read_output` 读回。输入框里发送键左侧有一个上下文用量环（参考 Codex 客户端）：弧长是最近一次主请求的输入 token 占可用输入容量的比例（70%、90% 变色），中间是整数百分比；悬浮用自绘浮层（原生 title 在 SVG 子元素上不弹）显示四行——上下文窗口、已用与剩余百分比、已用与总容量、这次输入的缓存命中率。压缩请求的输入也算满上下文，所以不作为口径。见 [Day 30 实践](../day-30/day-30-lab.md)。

## 7. 实现链路与数据

```text
网页提交问题
  → 观测台启动 agent 子进程
  → agent 请求本机模型代理
  → 代理转发到 X-Agent-Upstream 指定的上游
  → 请求、响应、终端与退出事件写入 .data/runs/
  → SSE 回放已有事件并推送新事件
  → 页面还原对话、轨迹与详情
  → 各进程的 span 写入 .data/traces/<trace_id>.jsonl，“调用链”按 trace 读取
```

agent 以 `-app-server` 启动：stdout 是 JSON-RPC 协议（问题与续聊上下文经 `turn/start` 传入，agent 发回 `turn/*`、`item/*`、记忆、能力、浏览器、子 agent 等通知，以及联网审批请求），stderr 是终端输出。页面需要的结构化信息只读通知；B0 之前的存档没有通知，由页面的兼容层把当时的日志行换算成同样的通知。协议细节见 [B0 实践](../bonus-protocol/protocol-lab.md)。

观测台把子进程 LLM_API_URL 指向自己的代理地址。模型选择与真实上游由 agent 的 llm.Providers 决定，代理接受声明的 https 上游；密钥从本地配置读取，Authorization 转发但不写入观测记录。

默认子进程是当前可执行文件，-dev 才使用 go run。每个任务进程独立，避免包级功能开关互相覆盖。agent 使用通用的 -history-stdin 恢复上下文，不读取观测台的存档路径。

附图存在当前租户的附件目录（平台是 `.data/attachments/`，租户是 `.data/tenants/<租户>/attachments/`），按内容寻址命名，`POST /attachments` 上传前先写审计 `user_attach`，`GET /attachments/<名字>` 只在当前租户的目录里找。消息、检查点与存档里只有 `attachment://` 引用：agent 发请求前才展开成 data URL，代理照原样转发，写存档前再换回引用，所以带图的对话存档里没有 base64，续聊从存档读回的也是引用。

事件包括 start、continue、request、response、stdout、stderr、exit，以及 B0 的 notify（协议通知）、approval（审批请求）与 D20 的 decision（高风险确认的答复）。start/continue 带这次交互的 trace_id，request 带 agent 的 chat span_id。观测台重启时读取已有存档，对话列表按最近活动排序。每个事件的 `seq` 在一条对话里只增不减：流式的 delta 只在内存里、不落盘，但也占序号，所以存档里的序号会有空档；重启后从存档里最大的序号接着编（10-19 之前是按内存里的事件数编号，重启后会和之前的序号重复）。原始请求响应、模型消息和工具结果都可能包含业务内容，运行数据留在 .data/，不复制到学习目录。

## 8. 自己动手观察

先新建普通对话，提问“先查学习笔记中的循环职责，再计算职责数量乘以25”，检查：

1. 同一个 Turn 是否出现检索、计算和最终回答；实际 Step 数由模型决定。
2. Step 输入是否随 assistant/tool 消息增长；条数是否与原始 messages 数组相同。
3. 续聊“再把结果乘以 3”，是否开启下一个 Turn 并保留此前结果。
4. 右侧原始卡片与工具结果是否能完整查看、复制。

上下文实验从页面“上下文实验”启动，观察压缩分隔线、摘要、输入量和终端统计；通过页面启动才能经过代理。普通 CLI 直连模型的运行不会自动出现在观测台，也无法事后补录。

检索对比从页面“检索对比”启动：包含多个独立上下文，不能作为普通对话续聊。各场景的方法和已有结果见 [Day 3 实践](../day-03/day-03-lab.md)、[Day 4 实践](../day-04/day-04-lab.md)。不需要下载或保存示例轨迹。

## 9. 兼容边界

工具和 messages 变化可从现有协议还原；原始 JSON 保留完整字段。流式响应（B1）由代理按 chunk 拼回非流式结构存档，页面与续聊不必区分；改成其他模型协议或不同命令行入口时，需要同步调整解析与页面。绕路判断依赖结果形状；空结果或错误标记变化时也需要复核规则。

页面展示的状态是执行记录，不是质量评分。用户理解、实验验收和生产风险分别见每日笔记、实践与 [PROJECT](../../PROJECT.md)。
