# Day 38：影响下一步的状态收在一处

## 学习目标与术语

学完能说明：一个跨轮、跨进程运行的 agent，有哪些状态会影响它的下一步；这些状态散在各处会出什么问题；为什么要收进一个结构、由检查点整体保存；哪些状态反而应该从“模型实际看到的内容”推出来；环境信息为什么只发变化的部分。

| 术语 | 通俗解释 |
| --- | --- |
| 影响下一步的状态 | 不在对话文字里、但决定 agent 下一步怎么做的东西：读过哪些文件、读入过哪些私有数据、用户放行过哪些外发、上次告诉模型的环境 |
| 状态快照 | 把这些状态和对话一起存下来，换进程后能原样接上 |
| 迁移 | 存储格式变了之后，读旧格式时把旧字段搬到新位置 |
| 视图派生 | 某个状态描述的是“模型的上下文里有什么”，就直接从上下文推出来，而不是另存一份 |

## 1. 状态散在各处的问题

一轮对话结束、下一轮由新进程接着做时，有些东西必须带过去：

| 状态 | 不带过去会怎样 |
| --- | --- |
| 读入过私有数据 | 新一轮把私有数据外发出去而不再询问 |
| 用户放行过的外发范围 | 同一范围又被问一遍 |
| 读过哪些文件、读时的内容 | 不能改文件（读后才写），或凭过时的内容改 |
| 上次告诉模型的环境 | 不知道环境变了没有，要么每轮重发、要么漏发 |
| 已经提醒过的上下文用量 | 每轮开头都再提醒一遍 |

如果这些状态各存各的——有的存进检查点的某个字段，有的每次从上下文里的提醒文字里“找回来”——就会出现两类毛病：

- **漏带**：新加一种状态时忘了存，换进程就丢了；
- **按文字找回不可靠**：上下文压缩后那段提醒没了，找不回来；文字格式一变就比较错。

收进一个结构、由检查点整体保存：新增状态只加一个字段；续跑取自己的，续聊取上一轮的，分叉只继承应该继承的。格式变了，读旧检查点时迁移。

## 2. 哪些状态该从视图推出来

并不是所有状态都应该另存一份。有些状态描述的恰恰是“模型的上下文里现在有什么”，例如“某个子目录的项目指令已经发给过模型”。上下文压缩后，这段指令可能已经被摘要掉了——这时以视图为准才对：视图里没有了，下次用到那个目录时就应该重新发。另存一份反而会和视图对不上。

判断方法：状态的真相在哪里。真相在外部世界（文件、用户的授权）的，存起来；真相就是上下文本身的，从上下文推。

## 3. 环境信息只发变化

环境信息（目录、分支、未提交改动、日期、权限……）每轮开头要让模型知道。办法：

1. 第一轮发一份完整的；
2. 之后每轮和上次告诉模型的那份**按字段**比较，只把变了的字段发出去（“权限改成了 plan，其余照旧”）；
3. 上下文压缩后，那份完整的环境信息已经并进摘要，下一轮重发一份完整的。

按字段比，比按整段文字比可靠：日期、改动计数这种字段变了，只发这一行；格式调整也不会被当成“环境变了”。

## 自测

1. 列出三种影响 agent 下一步、但不在对话文字里的状态。
2. 状态散在各处、每次从提醒文字里找回，会出什么问题？
3. 为什么“子目录指令发没发过”应该从视图推，而“读过哪些文件”应该存起来？
4. 环境信息为什么按字段比较？压缩之后为什么要重发整份？

### 自测答案

1. 读入过私有数据、用户放行过的外发范围、读过的文件与当时的内容、上次告诉模型的环境、已经提醒过的用量档位（任选三种）。
2. 新增状态容易漏存；压缩后提醒文字不在了就找不回来；文字格式一变，比较就出错。
3. 前者描述的是上下文里有什么，压缩后可能已经不在，以视图为准才对；后者的真相在外部（文件和读时的内容），上下文压缩不改变“读过”这个事实，要存。
4. 按字段只发变了的那一行，不会因为格式变化误报；压缩后完整的环境信息已经并进摘要，模型手里没有了，要重发。
