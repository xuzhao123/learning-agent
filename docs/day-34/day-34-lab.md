## 改动一览

| 终端客户端 | [chat.go](../../internal/chat/chat.go)，入口 `go run . chat` | 每一轮启动一个 `-app-server -ask-user` 的 agent（stdio，和 RunChild 一样的进程组与 Pdeathsig），`turn/start` 交问题与上一轮的检查点；流式显示正文与推理、工具调用一行开始一行结局；回答联网审批、高风险确认与提问（审批先写审计）；Ctrl+C 经 `turn/interrupt` 停止，再按一次强制结束 |

| 手动压缩 | [context_manager.go](../../internal/agent/context_manager.go) 的 `forceCompact` | `turn/start` 带 `compact: true`：这一轮第一次请求前先摘要（不走“只清旧工具结果”的捷径）；做不成只记一行，不让这一轮失败 |

## 1. 一轮在终端里的样子

```text
› 用计算器依次算 13*17、19*23、29*31（一次一个），每算完一个说一句结果。
我先算第一个。
▸ calculator {"expression": "13*17"}
  ✓ {"result":221}
13*17 = **221**。接着算第二个。
…
模型请求 4 次 · 输入 4534 · 输出 199 · 缓存 3840
```

推理以暗色显示；`▸` 是开始执行的工具，`✓`/`✗` 是结局。agent 自己的终端日志不在屏幕上，写在 `.data/[tenants/<租户>/]chat.log`。

输入只有 stdin 一个来源，按当时的状态解释：

| 状态 | 输入的一行是 |
| --- | --- |
| 有 agent 在等人回答（审批、提问） | 回答：审批是 `y`/`n`（外发类还有 `s` = 本对话内同一范围都允许），提问是选项编号或直接写的回答 |
| 一轮在跑 | 插话（`turn/steer`） |
| 空闲 | 新问题，或以 `/` 开头的命令 |

## 2. 会话命令

| 命令 | 做法 |
| --- | --- |
| `/turns` | 从最新一轮沿 `continues` 往回找检查点，列出每一轮的状态与问题 |
| `/resume <ID>` | 接着任意一轮聊（观测台或命令行跑过的也行），已撤销的拒绝 |
| `/fork <n>` | 下一轮接在第 n 轮后面，后面的检查点不动；先用 `Rewind(…, dryRun, "chat")` 算出之后各轮改过的文件，作为提醒交给下一轮 |
| `/compact` | 下一轮 `turn/start` 带 `compact: true` |
| `/rewind <n> [both\|files\|chat]` | 先预览（恢复、删除、冲突、bash 改过不会还原的），`y` 确认后执行；`files` 之后提醒“这些文件已恢复、对话没退，改之前先重读”；`chat` 之后提醒“这些文件的改动还在磁盘上” |
| `/mode <模式>`、`/approve [补充]` | 切换之后各轮的权限模式；批准计划 = 切到 edit 并以“计划已批准，切到 edit 模式，按计划开始执行。”开始下一轮 |

客户端不读 agent 的内部状态：显示只靠协议通知；会话命令读写的是检查点与快照（和 `go run . rewind` 一样的函数）。

## 3. 验证

格式化、`go vet`、`go build` 通过。DeepSeek 官方 `deepseek-flash`：

| 场景 | 结果 |
| --- | --- |
| 插话（终端） | 依次算三个乘法时输入“另外再帮我算一下 37*41”：一次在第 4 次请求前排进去（日志 `Steer:`），模型接着算了；另一次这一轮 5 秒内就结束了，插话随 `queued` 交回，客户端提示“没赶上这一轮”并作为下一轮发出 |
| 提问（终端） | 让模型先问起名风格：`ask_user` 给 4 个选项，回 `2`，结果是选项原文，模型按“幽默口语化”给了 3 个名字 |
| 计划批准与撤销（终端，临时 git 仓库做工作区） | `/mode plan` 下模型读文件给计划（plan 模式写不了）；`/approve` 切到 edit 后照做；`/rewind 2 files` 预览“恢复 1 个”、确认后文件回到原样，下一轮问“第一行是什么”，模型先重读，并说“你随后撤销了那次改动” |
| 只退对话 | 改了第二行后 `/rewind 1 chat`：文件不动、这一轮标成已撤销（`mode: chat`）；下一轮的消息里有提醒“对话退回到了第 1 轮之前，但之后各轮对这些文件的改动仍在磁盘上：notes.txt”，模型先读再答 |
| 手动压缩、分叉 | `/compact` 后下一轮先压缩（5951 → 4402 token），回答正常；`/fork 1` 后 `/turns` 只剩第 1 轮和新的一轮 |
| 联网审批（终端） | `request_network_access` 的提问在终端出现，回 `y`，当轮 curl 成功 |
| 观测台：提问 | 无头 Chrome 打开对话，提问卡片显示问题与 4 个选项；点第一个选项后卡片变成“你的回答：…”，模型按它回答；存档里有 `answer` 事件 |
| 观测台：插话 | 三条 `sleep 4` 的 bash 进行中，在输入框写“顺便最后再执行一次 echo d”回车：输入框清空，对话流里出现“插话 · …”，模型在第三条之后执行了 `echo d` |
| 观测台：批准计划 | plan 模式下“先给计划不要算”结束后出现按钮；点击后下一轮的 continue 事件 `permission: edit`，模型照计划算出结果 |

页面检查都没有脚本异常。

## 4. 回看 R3：含糊的问题

原对话（10-19）第 2 轮的问题是“你看下当前的仓库，刚刚实现了token的计算，为啥我没看到token的显示呢”。当时没有提问工具，模型 28 次请求后列了 5 种可能；用户真正的意思到第 3 轮才说清：观测台输入框旁边想要一个上下文用量显示。

回放：在 `.data/selfuse/` 里用 `git worktree` 还原到当时的代码（`2f863ce`，再去掉第 3 轮加的用量环），终端客户端 `-continue` 第 1 轮的检查点，发同一个问题，打开 `ask_user`；脚本只在出现提问时回答第 3 轮说清楚的意思（“我指的是观测台页面：输入框附近看不到当前这次对话用了多少上下文 token……”），其余参数照原对话（full、预算放宽到 40）。

| 回放 | 第一次提问 | 这一轮共几次请求 | 结果 |
| --- | --- | --- | --- |
| 原对话（没有提问工具） | — | 28 | 列 5 种可能 |
| 1 | 第 21 次 | 40（预算用完） | 问“你是在哪里没看到 token”，给 4 个选项；得到回答后又问一次“要不要加上”，回“按你的判断来”后开始实现，预算用完 |
| 2 | 第 28 次 | 40（预算用完） | 问法同上；得到回答后直接开始实现，预算用完 |
| 3 | 没有问 | 40（预算用完） | 一直自己查，预算用完 |

另有两次回放作废：它们和第 1 次共用一个 worktree，第 1 次已经在里面加了用量显示，后两次查到的是被改过的代码。重跑时每次都先把 worktree 还原。

结论：有了提问工具，模型会问，问得也对（选项里就有正确答案），但不是“探查几次之后”就问——3 次里 2 次在第 21、28 次请求才问，和原对话不提问时花的请求数差不多，1 次始终没问。光提供工具不够，“什么时候该问”要写进提示词：这一条放进 D37 的编码基础提示词消融，用这段回放做对照（问的时机、总请求数）。D37 在 Coconut 的 deepseek flash 上又回放了 6 次（默认提示词与加了“该问就问”的 extended 各 3 次）：都没有提问，全部用满 40 次请求，见 [Day 37 实践](../day-37/day-37-lab.md#11-r3-的该问就问)。回放用的 worktree 与检查点用完后已删除。

## 5. 已知边界

- 终端客户端是行式的，不是全屏 TUI：没有光标编辑、历史滚动和并排面板；推理与正文交错时只用颜色区分。
- 插话要等正在执行的模型请求或工具结束才进上下文；长时间的单个工具（比如等了几分钟的 bash）期间说的话要等它结束。真正打断仍是停止。
- `ask_user` 的等待和联网审批一样占着这一轮：人离开太久，到时按“没回答”继续。
- 只退一半的错位靠提醒说明；模型不看提醒也有“读后才写”兜底，但它可能基于过时的记忆回答问题。
- 观测台的撤销按钮仍只有“一起退”；只退一半只在终端客户端与命令行里。
- `/fork` 与 `/rewind` 按 `continues` 找轮次：同一轮被接着聊过两次（分叉过）时，撤销拒绝（不知道磁盘上是哪一支的结果），和 D29 一样。
