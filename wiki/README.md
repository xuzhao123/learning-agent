# Agent 体系学习 Wiki

这是一套按模块组织的 Agent 入门文档。它把已有的每日 notes 重新串成一条知识链：先看一次任务怎样运行，再理解每个模块为什么存在、怎样配合，以及哪里容易出错。

建议先看 [术语表](TERMS.md)，再读第一篇。每篇的第一节也会解释本篇用到的术语，不要求提前记住所有缩写。

每篇分成“基础理解”和“技术展开”两层：

- **第一次建立结构**：读前置术语、基础流程和例子，再跳到基础自测。
- **深入掌握机制**：读技术展开中的数据结构、公式、Go片段、故障窗口和参数取舍，完成进阶推演，再对照源码。
- **检查实现边界**：每篇“对照已有实现”说明哪些机制已在项目中，哪些仍是设计示意，避免把代码片段当作已经具备的生产保证。

准备面试时，使用 [Agent 工程面试题库](16-interview-preparation.md)：126 题覆盖原理、故障推演、系统设计与 Go 编码，附参考回答、追问、误区及 GitHub 资料入口；先从其中的 [24 道优先题](16-interview-preparation.md#先练这-24-题) 开始。
## 先建立四个概念

| 概念 | 通俗解释 |
| --- | --- |
| 模型 | 根据本次输入生成下一段输出，可以提出工具调用 |
| 工具 | 程序提供的具体能力，例如查资料、计算、读页面 |
| 执行循环 | 把模型决定、工具执行和结果反馈接起来的程序 |
| Agent | 围绕一个目标，借助模型和工具反复行动的整个系统 |

模型提出“查规则”，工具真的去查；模型提出“算补贴”，工具真的去算。控制程序负责判断这一步能不能执行、出了错怎么办、什么时候停下。

## 模块地图

```text
用户目标
  ↓
上下文管理 ── 选择本次要给模型看的信息
  ↑                ↓
检索 / 长期记忆    模型调用与执行循环
                   ↓
            工具选择、校验与编排
              ├─ 本地函数
              ├─ MCP 工具服务
              ├─ 浏览器 / 受限代码执行
              └─ 子 Agent
                   ↓
                执行结果
                   └────────→ 回填上下文，再决定下一步

运行时：约束成本与时间，处理失败、超时和取消
持久化：保存进度，处理任务中断与恢复
调度：安排多个任务由谁执行、何时执行
安全：限制每条调用能读取、修改和外发什么
观测与评估：记录发生的过程，检查结果是否满足目标
Skills：按需补充某类任务的做事方法
```

图中的模块是职责划分，不要求一个模块对应一个服务或进程。

## 贯穿全书的例子

用户提出：

> 我去上海出差三天，查一下补贴规则，算出金额，再整理一份中文报销说明。

后续章节会逐步给这个任务增加条件：资料里有不同版本，工具可能超时，用户希望下次仍使用中文表格，任务可能中断，网页也可能夹带恶意指令。所有金额和片段都用于解释机制，不作为真实制度或实验结果。

你可以一直追问四件事：

1. 这条信息从哪里来，谁负责保存？
2. 模型这一次真正看到了什么？
3. 哪个程序实际执行了动作，权限由谁检查？
4. 如果在这里失败或中断，怎样知道外部世界已经发生了什么？

## 怎样使用这套文档

每篇依次提供术语、流程、具体例子、取舍与自测。先自己解释自测题，再对照解析；能用另一种任务复述流程，比背缩写更有用。

Wiki 的正文讲通用机制。实际代码和动手步骤链接到原有 lab；每日 notes 保留课程顺序与更深入的资料。公共启动与配置见 [项目 README](../README.md)。

这套知识覆盖现有 Day 1–12 与 Skills、子 Agent、模型路由扩展。完整评测、注入攻防、多租户与生产交付仍需后续实践，本文不会把概念介绍等同于已经完成这些能力。
