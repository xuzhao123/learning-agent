# 05 · 检索与 RAG：让答案有可以核查的依据

RAG 解决的问题是：回答需要的事实不在本次上下文里，怎样从外部资料找回来。

[阅读目录](README.md) · [技术展开](#技术展开) · [基础自测](#自测)

## 先认识术语

| 术语 | 通俗解释 |
| --- | --- |
| RAG | 检索外部资料，再根据资料生成回答 |
| Chunk | 被单独检索的一段内容 |
| Embedding | 用模型把文本编码成一组数字 |
| Similarity | 向量之间的接近程度，不是事实可信度 |
| 余弦相似度 | 比较向量方向的接近程度，范围是 −1 到 1 |
| Top-k | 最多取前 k 个候选 |
| BM25 | 用词项的出现、稀有程度和文本长度排序 |
| RRF | 用检索名次融合多路结果 |
| Rerank | 对已召回的候选做更细的判断 |

## 一份资料要经过两个阶段

```text
建索引：资料 → 清洗 → 切块 → 保存来源 → 生成表示 → 索引
提问时：问题 → 召回 → 过滤 → 融合/重排 → 少量片段 → 模型
```

建索引决定最小能找到什么。在线检索决定这次需要哪几段。

模型最终读到的是片段文字和来源，不是向量。向量只帮助程序找出候选。

## 在 Agent 里怎样接入

可以每次提问前固定检索，也可以把检索注册成工具。前者适合稳定问答流程；后者适合多步任务，让模型根据反馈补充查询。也可以结合两者。

工具式检索沿用同一循环：

```text
模型提出 search_docs
  → 工具取回“补贴每日 180 元，适用普通工作日”
  → 结果作为 tool 消息进入历史
  → 下一次模型请求根据它决定计算或继续核查
```

模型可能跳过检索，也可能反复搜索。需要明确何时必须查资料，并限制低收益的重复查询。

## 切块为什么重要

片段只有“每日 180 元”，会失去适用人群和条件。片段把整份十页制度都装进去，又可能混入其他城市与版本，检索变模糊。

优先按标题、段落和语义边界切分，保留制度名、版本、时间和适用范围。小片段命中后返回相邻上下文，也能帮助补足条件。

块的长度应适配实际向量模型；增加标题或背景以后，还要再次检查总长度。不能让编码器悄悄截掉“节假日除外”这类关键条件。

## 向量、关键词和重排怎样配合

向量擅长找到同义表达：“出差补助”可能接近“差旅津贴”。关键词更适合精确标识：“制度 DOC-12”不能被语义接近的 DOC-21 替代。

```text
向量召回 ─┐
          ├→ 合并去重 → 重排 → 选取证据
BM25 召回 ─┘
```

BM25 的分数和余弦相似度量纲不同，不宜直接相加。RRF 根据各路名次投票：两路都排在前面的候选通常更占优。

重排器会更仔细地读问题和候选，比如判断“补贴标准”与“发票提交要求”哪个支持当前问题。但它看不到未被召回的材料，因此不能补救召回阶段完全漏掉的事实。

建库与查询必须用匹配的模型和处理规则。不同模型的向量，即使维度相同，也不能直接比较。

## 给片段补背景：Contextual Retrieval

孤立的“它只接受 PDF”很难匹配“报销系统的发票格式”。可以从来源中补出“报销系统的要求”，再对“背景 + 原文”建索引。

背景帮助找到片段，不能改写原始事实。没有可靠来源时，不应让模型猜“它”指什么。背景也是派生数据，要检查错误、缓存和失效。

这类方法有预处理成本，是否改善效果要在自己的问题集上测量。[Anthropic 的原始说明](https://www.anthropic.com/engineering/contextual-retrieval)介绍了这一设计与实验设置。

## k、阈值与引用

k 太小可能漏掉条件；太大会带回噪声。阈值用来过滤明显无关候选，但相似度不是“答案有多大概率正确”。

引用要同时核查：

1. 来源确实在本次实际取回的结果中。
2. 正文支持答案里的数字、条件和判断。
3. 时间、权限和版本适合当前任务。

只引用一个相关标题，不能证明金额成立。资料缺失或版本冲突时，应说明不确定，或继续做有限的补充检索。

## 技术展开

### 进阶术语：倒排索引、IDF 与模型空间

| 术语 | 含义 |
| --- | --- |
| 倒排索引 | 从词找到出现该词的片段与词频 |
| TF / DF | 当前片段中的词频 / 包含这个词的片段数 |
| IDF | 稀有词的区分力权重 |
| 模型空间 | 某个编码器定义的向量坐标体系 |
| Cross-encoder | 把问题和候选一起编码，直接判断关联的模型 |
| ANN | 近似最近邻检索，用一定召回损失换取大规模搜索速度 |

### 向量相似度怎样计算

```text
cos(q,d) = sum(q_i*d_i) / (sqrt(sum(q_i^2))*sqrt(sum(d_i^2)))
```

把向量归一化为单位长度后，余弦就是点积。Go 的核心计算片段：

```go
func dot(a, b []float32) (float64, error) {
    if len(a) == 0 || len(a) != len(b) {
        return 0, errors.New("向量维度不匹配")
    }
    var score float64
    for i := range a {
        x, y := float64(a[i]), float64(b[i])
        if math.IsNaN(x) || math.IsInf(x, 0) ||
           math.IsNaN(y) || math.IsInf(y, 0) {
            return 0, errors.New("向量包含非有限值")
        }
        score += x * y
    }
    return score, nil
}
```

需要 errors、math。归一化与零范数拒绝应在入库/查询预处理做；未归一化时，这段 dot 不是余弦相似度。

N 个 D 维 float32 向量，纯数值存储约为 4ND 字节。N=100,000、D=1,024 时约 391 MiB，还不含文本与索引对象；暴力检索每题约 1.024 亿次乘加。因此规模扩大后才考虑 ANN，而不是一开始必须装向量数据库。

### BM25：公式中每项实际做什么

本工程使用一种常见的正值平滑 IDF：

```text
IDF(t) = ln(1 + (N - DF(t) + 0.5)/(DF(t) + 0.5))

BM25(D,Q) =
  sum over distinct query terms t:
    IDF(t) * TF(t,D)*(k1+1) /
    [TF(t,D) + k1*(1-b+b*len(D)/avgLen)]
```

| 参数 | 增大时主要影响 |
| --- | --- |
| k1 | 词频贡献更慢达到饱和，更重视重复出现 |
| b | 更强地按文本长度归一化 |
| DF | 越多片段含这个词，IDF越低 |

固定 N=3、DF=1、len(D)=avgLen、k1=1.2：

- IDF≈0.9808。
- TF=1 时词频因子为 1，得分≈0.9808。
- TF=2 时词频因子为 1.375，得分≈1.3486，并不是翻倍。
- TF 增大时，词频因子逐渐接近 k1+1=2.2。

不同 BM25 实现的 IDF、分词、查询词频处理可不同，不能只看“都是 BM25”就比较分数。理论背景见 [Stanford 信息检索教材](https://nlp.stanford.edu/IR-book/html/htmledition/okapi-bm25-a-non-binary-model-1.html)。

中文 bigram 把“报销系统”变成“报销、销系、系统”；编号 ERR-4012 还需整词保存。否则精确匹配会退化成若干数字的部分匹配。

### RRF 为什么不需要分数量纲

```text
RRF(d) = sum over retrieval routes r: 1/(c + rank_r(d))
```

c 是平滑参数，不是 top-k；一路没取回该候选，贡献为 0。

取 c=60：

- A：向量第 1、BM25 第 2，RRF≈0.032522。
- B：只有向量第 2，RRF≈0.016129。

A 得到两路支持，比分数量纲不同直接相加更容易解释。它仍不是相关概率，也不保证比单路最优结果更好。

同一条记忆被切成三个块时，要先按记忆去重再计名次；否则长记忆可能凭块多占满候选或重复得分。

### 重排和上下文预算怎样相互制约

```text
两路较宽召回 → 去重融合 → 小批候选重排
                         → 相关性/有效性过滤
                         → 按token预算取最终原文
```

召回量、重排量、最终注入量是三个不同参数。取回 50 条不意味着把 50 条全文都塞给主模型。

LLM 重排返回的 ID 必须属于候选集，字段合法，重复 ID 和遗漏项有明确处理。模型自报 0.9 不能当作经过校准的“九成正确”。

来源背景能补足指代，但原文、来源和版本仍是依据；索引指纹应包含模型、维度、预处理/指令、切块规则和语料版本。

### 进阶推演

1. 同一语料换了 embedding 模型，维度恰好相同，旧索引能继续用吗？  
   不能。坐标语义可能不同，维度相同只保证可做乘法，不保证相似度有意义。

2. 重排把一条过期制度排第一，为什么仍不能直接回答？  
   相关性排序和有效性检查不同；版本、时间、权限要独立过滤或核查。


## 自测

1. 检索结果排序第一，是否一定可以作为答案？  
   不一定。最相似的候选也可能不支持结论、已过期或不在权限范围。

2. 为什么精确制度编号需要关键词检索补充？  
   编号差一个字符可能指不同对象，语义相似度无法保证精确匹配。

3. k 从 3 改成 30，一定提高回答质量吗？  
   不一定。召回可能增加，但更多噪声、窗口占用与误引用也会增加。
