读图要点

一个核心，多种界面。终端、IDE、CI 和 SDK 都是同一个 harness 的客户端，靠一套事件协议驱动。审批是 harness 发给界面的请求，没人回答就不执行。

沙箱和审批是两条独立的轴。沙箱由操作系统强制，只管 shell 及其子进程；审批决定越界时问不问、问谁。规则和 hook 看的是命令文本，沙箱管的是实际的系统调用，所以两者要一起用。

上下文按缓存来设计。稳定内容放前面，历史只追加；环境或文件变了，用追加一条提醒来表达，不改写前缀。压缩时先丢旧的工具输出，再做摘要。

能配置的都不写死。项目指令、权限规则、hooks、skills、MCP、子 agent 都是文件，按托管策略、项目、用户分层合并。harness 代码只提供机制。
